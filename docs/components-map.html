Early Bird

A concert watcher for Karan: it checks the acts he follows across ticketing APIs and listing pages every half hour, and emails him the moment a show appears — with the early-bird window flagged and Bengaluru dates on top.

Next.js on Vercel Supabase Postgres Gemini Flash — extract · match · filter ScrapingBee Gmail API Google Calendar Vercel Cron · 30 min

01The pipeline

One scan run walks the whole path below. Every stage writes its outcome to scan_runs, so a source that blocks or times out degrades that run instead of failing it.

02One show, three sources, one row

The same Bengaluru date shows up on Ticketmaster, BookMyShow and District with three different spellings. Collapsing them is what makes first_seen_at mean anything — and first_seen_at is the field that proves an alert fired at announcement, not hours later.

04What Gemini returns

The model is held to one shape. Anything that does not validate is reprompted once and then dropped, so a bad extraction never reaches the feed as a half-filled card.

// one element per detected show; the whole response is an array
{
  artist:              "Prateek Kuhad",
  artist_slug:         "prateek-kuhad",      // matched against the registry
  venue:               "Phoenix Mall of Asia",
  city:                "Bengaluru",          // Bangalore normalises to this
  country:             "IN",                 // anything else is discarded
  date:                "2026-11-14",         // ISO, null if only "November"
  ticket_url:          "https://…",
  early_bird_status:   "available",          // available | upcoming | sold_out | none | unknown
  early_bird_deadline: "2026-10-19T18:30:00+05:30",
  price_from:          1499,                 // INR, null when not listed
  confidence:          0.91                  // below 0.6 → held for review, no alert
}

05What makes an alert fire

New row

An event_key never seen before. This is the announcement alert, and first_seen_at records the minute it was caught.

Early bird opens

early_bird_status moves from upcoming to available. Sent as urgent, with the deadline and a countdown.

Deadline inside 24h

A nightly sweep catches windows about to close on shows already in the feed. One reminder per event, never repeated.

Date or venue moves

A watched field changes on an existing row. Sent quietly, showing the old value beside the new one.

Bengaluru events sort to the top of every email and carry a city badge. Price changes, description edits and new source sightings update the row but send nothing — that is what keeps the inbox worth opening.

06Build order

  1. Schema and seeded artist list in Supabase — nothing to show, everything depends on it.
  2. Ticketmaster adapter only, straight through Gemini into events. One source, end to end.
  3. Dedupe and first_seen_at, proven by running the same scan twice and getting one row.
  4. Dashboard feed with Bengaluru pinned, so there is something to look at.
  5. Gmail alert on insert, fired manually from the Scan now button.
  6. Vercel Cron, with the secret on the route.
  7. Bandsintown, then BookMyShow and District, then the search fallback.
  8. Google Calendar “I'm going” action, early-bird countdown, alert history, per-source health, README.

Steps 1–5 are the submittable system. Everything after widens coverage; nothing after changes the shape of the map above.
